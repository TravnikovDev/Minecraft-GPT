# Recreating Minecraft bot gameplay as rendered 3D animation in Blender (state as of 26 November 2026)

Scope note: research was done on 2026-11-26. Version numbers and dates below come from the tools' own pages, the public GitHub API and repository source files fetched that day. Where a claim comes only from a search-engine summary and the page itself could not be opened, it is marked "(search summary, not opened)".

## 1. MCprep (Moo-Ack! Productions): version, Blender 5.x support, features, licence, scriptability

### Takeaway
MCprep is alive and current: v3.6.3 (12 July 2026) declares support for Blender 2.83 through 5.2 and ships resources refreshed up to Minecraft 26.2. It is GPL-3.0 code with CC-BY assets, every feature is an ordinary `bpy.ops.mcprep.*` operator, and its own test suite runs those operators with Blender in `--background` mode, so it can be driven from a headless Python script.

### Inferences
- Because the operators are plain registered operators and the project's CI-style tests run them in `--background`, a headless build script (or the Blender MCP agent) can do the whole MCprep chain: import OBJ → `prep_materials` → `mob_spawner` → `applyskin(filepath=...)` → `add_mc_sky`. Operators that need a specific selection/active object or a 3D-viewport context may need a context override; that part is not confirmed for every operator.
- MCprep is not on the per-operator level a "headless API" with documentation; one reads operator properties from the source. For an agent with `execute_blender_code`, that is workable.
- Mob rigs lag behind block resources ("excluding mobs which are subject to community contributions"), so mobs added in 2025–2026 game drops may be missing.
- The bundled default texture pack means MCprep-prepped scenes contain Mojang textures out of the box; see the licensing section.

### Gaps
- I did not test MCprep 3.6.3 on Blender 5.2 LTS on Apple Silicon; the "through 5.2" statement is the maintainers' claim only.
- Not verified whether `mcprep.animate_textures` and the geometry-node weather effects work headless on 5.2.
- Whether MCprep is distributed through extensions.blender.org or only through theduckcow.com was not checked (the site was not opened).

## 2. World export tools: Mineways, jmc2obj, USD exporters, Chunky; version support, macOS, command line

### Takeaway
For a Mac-based scripted pipeline the practical exporter is **jmc2obj** (Java, full command line with `--area`/`--height`/`--resource-pack`), but its 26.1 world-format fixes exist only on the master branch (August 2026), not in a tagged release. **Mineways** has the best version coverage (26.3 and earlier, updated October 2026) and real scripting plus an experimental `-headless` mode, but it is a Windows program that runs on Mac only through Wine-type wrappers. Chunky is not a route for character animation: stable is stuck at 1.20.4 and it does not render most entities.

### Cited Findings

- Current version is **Mineways 14.02** for Windows, "Last updated October 23, 2026", 280 MB download; works with "Minecraft: Java Edition, versions 26.3 and earlier" — [Mineways home](https://www.realtimerendering.com/erich/minecraft/public/mineways/)
- Recent releases: v14.02 (2026-10-23), v14.01 (2026-10-03), v14.00 (2026-09-27, "Add reading Minecraft 26.3 new format. 26.3's palette structure is different from 26.2"), v13.01 (2026-09-02, blocks from 26.2) — [Mineways GitHub releases](https://github.com/erich666/Mineways/releases)
- Exports OBJ and "now exports using photorealistic resource packs to Pixar's USD format" — [Mineways home](https://www.realtimerendering.com/erich/minecraft/public/mineways/)
- Scripting: `.mwscript` text files; command line `mineways.exe [-headless] [-w X Y] [-m] [-s UserSaveDirectory|none] [-t terrainFile] [-l log] [-suppress] [-zl #] [file1.mwscript ...]`. ### Inferences
- Version matrix for the bot's range: **1.21.x worlds** → jmc2obj 128 release (to 1.21.9), Mineways 14.02, MiEx, Chunky 2.5.0 snapshot. **26.1 worlds** → Mineways 14.02 (stated "26.3 and earlier"), jmc2obj master/beta build only (not release 128), Chunky 2.5.0 snapshot only, MiEx unconfirmed.
- jmc2obj is the natural fit for an automated Mac pipeline: it is a Java jar (runs on Apple Silicon with a JDK), takes an area in block coordinates and a height range on the command line, and MCprep is built around its OBJ output. The catch for 26.1 is depending on an unreleased build.
- Mineways on an M1 Max means running the current Windows exe under Wine/CrossOver/a VM; the packaged Wineskin build (12.09) is two major versions behind the 26.x format work, so it very likely cannot read 26.1+ worlds. That is a fragile dependency for an automated pipeline.
- All world exporters need the **world save folder**. If the bot plays on a server the creator runs locally, the save is available (ideally copied or flushed with `save-all` first). On a remote server it is not, and only the bot's own block log can describe the scene.
- A world export is a static snapshot. Blocks the bot breaks or places during the clip still need to be animated separately (hide/show or scale keyframes on per-block objects), so exporters alone do not replay a session.
- Chunky cannot show the bot (entities largely unsupported), so it is useful only for still establishing shots or background plates, not for the route described here.

### Gaps
- Whether the Mineways 12.09 Wineskin build opens 26.1 worlds: not stated anywhere I could read; the release in which Mineways first read the 26.1 format was not identified.
- Whether MiEx reads 26.x worlds, has a command-line mode, and how well its USD imports into Blender 5.2 (materials, instancing): the README does not say and the wiki was not opened.
- "Minecraft Assets Explorer", "Minecraft Importer" and mcworldlib-based Blender addons that read region files directly: I found no current information on them in this session; their 5.2/26.1 status is unknown.
- jmc2obj headless behaviour on macOS (does it need a display?) was not tested; the options exist in source but I did not find a usage page.

## 3. Reconstructing the scene without a world export (bot block dump, schematic importers, prismarine tools)

### Takeaway
There is no mature, cross-platform "schematic → Blender" importer: the one active addon (Mine2Blend, .litematic/.schem) is a Windows-only beta, and the others are abandoned or tiny. The realistic route is the bot's own data: either a custom JSON block dump meshed by a Python script in Blender, or prismarine-viewer's mesher, which already runs next to Mineflayer and has an example that exports world parts as 3D models.

### Cited Findings
- **Mine2Blend** imports `.litematic` and Sponge `.schem` (v2/v3) into Blender with materials (transparency, glass, water, plant cut-outs, tint); version 0.5.12 beta; requires Blender 4.2 LTS+ (tested on 5.1.2); **Windows 10/11 x64 only** ("no macOS / Linux runtime yet") because it bundles a Node.js converter runtime; `.schematic` and `.nbt` not supported; GPL-3.0-or-later per README; last push 2026-11-19; 8 stars — [Mine2Blend README](https://github.com/CAT-YC/Mine2Blend)
- Other GitHub hits: `lmbmnl/Schematics2Blender` ("import minecraft schematics into blender", GPL-3.0, pushed 2026-10-04, 0 stars); `scribblemaniac/MCEdit2Blender` (old MCEdit `.schematic` only, last push 2015-07-31) — [GitHub repository search](https://github.com/search?q=minecraft+schematic+blender+import&type=repositories)
- **Litemapy** is a Python library "to read and edit Litematica's schematic file format" (search summary, not opened) — [SmylerMC/litemapy](https://github.com/SmylerMC/litemapy)
- **prismarine-schematic**: "Read and write schematic of any minecraft version, provide them in a convenient and stable API"; MIT; pushed 2026-10-06 — [prismarine-schematic](https://github.com/PrismarineJS/prismarine-schematic)
- **prismarine-viewer** (v1.33.0, MIT, 408 stars, pushed 2026-10-06) is a "Web based viewer for servers and bots" built on three.js 0.128. Its README lists: "Record view as video file" (headless example with a `frames` option), "Streaming video to a python script", "Visualize a world, without a bot" (standalone), and "Export parts of worlds as screenshot or 3d models" — [prismarine-viewer README](https://github.com/PrismarineJS/prismarine-viewer)
- The exporter example says: "run `node 3dmodel.js` to get 3d models"; headless via `xvfb-run`; "3D files can be displayed by https://gltf.insimo.com/" — [prismarine-viewer exporter example](https://github.com/PrismarineJS/prismarine-viewer/tree/master/examples/exporter)
- Version support conflict: the README lists supported versions up to 1.21.4 (other versions of the same major "render with the textures and models of the closest supported one"), while `viewer/lib/version.js` on master lists `'26.1'` in `supportedVersions` — [prismarine-viewer README](https://github.com/PrismarineJS/prismarine-viewer); contradicted by [version.js](https://github.com/PrismarineJS/prismarine-viewer/blob/master/viewer/lib/version.js)
- A third-party Mindcraft-style project notes that prismarine-viewer's bundled browser assets only know versions up to 1.21.4 out of the box and newer versions need extra asset generation (search summary, not opened) — [dsh-minecraft-agent README](https://raw.githubusercontent.com/jcs130/dsh-minecraft-agent/57d9e4a5588c0f3ae728c623bf0c41f733e945ad/README.en.md)
- Mineways itself reads and writes `.schem` files (v13.01 fixed ".schem export and import of stairs" and reading `.schem` files taller than 256) — [Mineways GitHub releases](https://github.com/erich666/Mineways/releases)
- MCprep has a JSON block-model importer (`mcprep.spawn_model`, `mcprep.import_model_file`; "overhauled JSON model importer" in 3.6.3) and a Material Library that loads a Minecraft material onto a slot — [MCprep releases](https://github.com/Moo-Ack-Productions/MCprep/releases), [spawner/mcmodel.py](https://github.com/Moo-Ack-Productions/MCprep/blob/master/MCprep_addon/spawner/mcmodel.py)

### Inferences
- Three workable designs, in rising effort:
  1. **Bot JSON dump → Python mesher in Blender.** The bot writes `{origin, size, palette, blocks[]}` for a box around itself (for example 48×32×48 = about 74k cells, mostly air or hidden). A bpy script culls hidden faces and builds one mesh per block type (or one mesh with a texture atlas), with Nearest-filtered 16×16 textures. Full cubes cover most terrain; stairs, slabs, fences, torches, plants and water need special cases or get approximated. This has no version dependency at all, because the bot already has block names through minecraft-data.
  2. **prismarine-viewer mesher → glTF → Blender.** The viewer already turns chunk data into three.js geometry with correct block models and an atlas; the exporter example shows a 3D-model output path that Blender's glTF importer can read. This gives proper non-cube shapes for free, at the cost of an old three.js stack, headless GL on macOS, and the unresolved 26.1 asset question.
  3. **Bot → `.schem` via prismarine-schematic → Mineways (reads .schem) → OBJ → MCprep.** Possible on paper but chains a Windows tool; not attractive on a Mac.
- Design 1 also makes block changes easy to animate: each logged `blockUpdate` in the clip window becomes a separate small object with a visibility/scale keyframe at the logged time, laid over the static base mesh.
- Instancing one cube per block with geometry nodes is fine for a few thousand visible blocks; for larger regions a merged, face-culled mesh is the safer choice for EEVEE memory and export time. (Blender 5.2's EEVEE notes mention instancing-heavy scenes being up to twice as fast; see section 6.)
- Mine2Blend's approach (bundled Node converter) suggests the community's own best importer is essentially "prismarine-style JS mesher wrapped in an addon", which supports design 2 as a sound architecture.

### Gaps
- I did not run `examples/exporter/3dmodel.js`; the output format (glTF is implied by the viewer link, not stated) and its quality in Blender are unverified.
- No evidence found of any existing tool that builds Blender scenes from a Mineflayer bot's live chunk data or from a logged timeline.
- `.nbt` structure-file importers for Blender: none found.
- Whether `lmbmnl/Schematics2Blender` works on Blender 5.2 or macOS is unknown (0 stars, README not opened).

## 4. Characters: free player/mob rigs, licences, custom skins, procedural animation from a timeline

### Takeaway
MCprep already bundles CC-BY player and mob rigs and a scriptable skin swap (`mcprep.applyskin(filepath=...)`), which is the lowest-friction path; standalone alternatives exist (Thomas Rig Legacy under GPL, Woodplank Rig with explicit monetised-video permission, CC-BY/CC0 rigs on BlendSwap and Sketchfab). Driving a blocky rig from a logged position timeline is conceptually simple, but I found no ready-made tool that does it.

### Cited Findings
- MCprep's bundled player rigs: Fancy Feet Player (TheDuckCow), Fancy Feet Slim, Fancy Feet Armor (zNightlord), Simple Player and Simple Slim Player (BoxScape Studios, modified), Shapekey Player, Story Mode Rig (Trainguy9512), VMcomix Steve; the README asks users to credit the respective creator; assets are CC-BY — [MCprep README](https://github.com/Moo-Ack-Productions/MCprep)
- MCprep mob rigs include (among others) cow, squid, spider, silverfish, endermite by Nils Söderman (rymdnisse); pig, chicken, enderman, skeleton, ghast, blaze, guardian, shulker by Trainguy9512; creeper and bat by TheDuckCow; sheep and rabbit by HissingCreeper; fox, bee, panda, piglin, pillager, ender dragon, slime, husk and others by BoxScape Studios — [MCprep README](https://github.com/Moo-Ack-Productions/MCprep)
- Skin application in MCprep: Skin Swapper can apply a skin from a file or download one by username; operators `mcprep.applyskin` (takes `filepath`), `mcprep.applyusernameskin`, `mcprep.spawn_with_skin` — [MCprep README](https://github.com/Moo-Ack-Productions/MCprep), [materials/skin.py](https://github.com/Moo-Ack-Productions/MCprep/blob/master/MCprep_addon/materials/skin.py)
- **Thomas Rig Legacy** is on Blender Extensions: an advanced edit of the Thomas Rig by Thomas Animations, used with permission, GPL v3 or later; it can load original textures from a Minecraft `.jar` (search summary; the page returned HTTP 403 when opened) — [Thomas Rig Legacy](https://extensions.blender.org/add-ons/thomas-rig-legacy/)
- **Woodplank Rig** grants permission for personal animations, monetised YouTube videos, social media content and freelance work; redistribution of the raw .blend files is not allowed (search summary, not opened) — [Woodplank Rig](https://woodplankmc.com/b/l3K8D)
- Other free rigs: several CC-BY Minecraft rigs and a CC0 "Minecraft Rigs And Blocks" on BlendSwap; "Minecraft Player (Rigged)" by Captain Allen on Sketchfab under CC Attribution (search summary, not opened) — [BlendSwap rig](https://blendswap.com/blend/3221), [Sketchfab rig](https://sketchfab.com/3d-models/minecraft-player-rigged-62c02461bfba4dd9a62688c37bf6a22a)
- Blender Studio hosts a paid "Minecraft Animation Workshop" by Dillon Gu covering the pipeline from world import to rendering (search summary, not opened) — [Blender Studio](https://studio.blender.org/training/minecraft-animation-workshop/)

### Inferences
- A Minecraft-style character is six boxes with pivots at the neck, shoulders and hips. Procedural animation from a log needs only: root location from logged position (interpolated from 20 Hz ticks to 30 fps); body yaw from logged yaw; head pitch/yaw from logged look direction; leg and arm swing as a sine wave whose phase advances with horizontal distance travelled (so feet do not slide) and whose amplitude follows speed; a one-shot right-arm swing action triggered on `dig`, `place`, `attack` events; a held-item object parented to the hand bone and swapped on `heldItemChanged`. This mirrors how the game itself animates players (limb swing driven by movement distance), which is why it looks right with little work.
- In bpy this is a few hundred lines: either direct keyframes on pose bones or NLA strips of small pre-made actions (walk cycle, swing, hurt, eat) placed at event times. For a simple six-part character, skipping third-party rigs and building an own armature in code avoids IK/driver complexity in rigs such as Fancy Feet and removes a licence dependency.
- Things that are not free from a position timeline: jump arcs (need logged y at tick rate, which Mineflayer has), block-breaking crack overlay (10-stage texture swap on the target block), item pickup/drop, mob behaviour (mobs need their own logged entity positions, which the bot sees via entity events), and camera work. Camera direction is the part that decides whether the clip looks good and is the least automatable.
- Because Sketchfab and Poly Pizza are reachable from the creator's Blender MCP server, a CC-BY or CC0 blocky character can also be imported that way; licence terms must be checked per model.

### Gaps
- "BlackOpal"/"SACR" rigs: the search returned nothing verifiable on their current availability or licence.

## 5. Stylised alternative: original low-poly voxel look instead of Mojang textures

### Takeaway
An original voxel look (own block palette, original robot character) takes the Mojang "assets" (textures, models) out of the picture entirely, which removes the least clearly licensed part of this route; the name and "not official" rules still apply whenever the videos say "Minecraft". Tooling exists (MagicaVoxel import extension, geometry-node voxelisers), and the scene generator from section 3 works the same with flat-colour or self-drawn textures.

### Cited Findings
- Mojang defines "our assets" as "the code, software, graphics, textures, images, models, sounds and other audio from any of our games and any videos or screenshots taken from our games", and "our brand" as "any names, related logos, fonts, textures, and any other distinctive characteristics of any part of our name and games" — [Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)
- The guidelines' catch-all: "If something isn't covered by these guidelines and we haven't otherwise said it's okay, that probably means we don't want you to do it" — [Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)
- **MagicaVoxel VOX format** importer by AstrorEnales is on Blender Extensions (version 1.5.7, listed as compatible with Blender 4.2 LTS and newer; several meshing, colour and material modes) (search summary, not opened) — [Blender Extensions: MagicaVoxel](https://extensions.blender.org/add-ons/blender-magicavoxel/)
- **BlockBlender** (Joey Carlino) "turns anything into Minecraft blocks in real time using geometry nodes"; it has been renamed **VoxelVision 4**, a paid addon whose changelog lists an upgrade to Blender 5.0 and to Blender 5.2 LTS (24 July 2026); a free version includes 32 blocks; an FAQ entry still says only 4.5.x is supported, which conflicts with the changelog (search summary, not opened) — [VoxelVision 4 on Superhive](https://superhivemarket.com/products/blockblender-2), [BlockBlender on itch.io](https://joeycarlino.itch.io/blockblender)
- Voxility/Voxelity Pro is a paid voxel file-format exchange addon listed for Blender 2.93–5.0 (search summary, not opened) — [Superhive listing](https://superhivemarket.com/products/voxelity-pro-voxel-file-format-exchange)

### Inferences
- Legal effect: with own textures and an own character, the footage contains none of the items in Mojang's "assets" definition. What remains is (a) the word "Minecraft" in titles/descriptions (naming rules, disclaimer), and (b) the general look. "Distinctive characteristics" in the brand definition is broad, so a pixel-for-pixel imitation of the vanilla look is not obviously "clean"; a clearly different palette and an original robot design is. This is my reading of the text, not legal advice, and Mojang says it will not advise on specific projects.
- Stylistic effect: a consistent original look makes the series recognisable as its own show (useful next to the creator's other cartoon series, which already shares the Blender + Remotion pipeline), hides the fact that fine block details (stairs, fences, redstone) are approximated, and lets the bot be an original robot character rather than a Steve skin. The cost is that viewers lose the instant "this is real Minecraft" recognition that helps Minecraft content travel, and a devlog about real bot behaviour may feel less "proven" when it is not game footage.
- A middle path: original textures drawn in the 16×16 pixel style (a self-made "resource pack") applied through the same mesher. It reads as Minecraft-like, is the creator's own artwork, and can be swapped for vanilla textures later without changing the pipeline.
- BlockBlender/VoxelVision solves the opposite problem (voxelising arbitrary meshes into blocks); it is useful for stylised set dressing, not for replaying bot data. MagicaVoxel is useful for hand-authoring the robot character and props.
- Blender MCP asset sources (Poly Haven, Poly Pizza, Sketchfab) help only on the stylised path; a vanilla-look scene needs Mojang textures, which those libraries do not legitimately provide.

### Gaps
- No legal source found that analyses "Minecraft-style animation with original assets" specifically.
- Blender 5.2 compatibility of the free MagicaVoxel extension was not confirmed on its page.

## 6. Render cost: EEVEE vs Cycles on an M1 Max at 1080×1920, 1200 frames

### Takeaway
I found no trustworthy published seconds-per-frame figure for EEVEE on an M1 Max in Blender 5.x at 1080×1920. The anecdotal range for EEVEE is roughly 1–30 s per frame depending on scene and settings, which puts 1200 frames anywhere from about 20 minutes to several hours; the creator's existing series on the same machine and Blender version is a far better predictor than anything online.

### Cited Findings
- Blender 5.2 LTS was released 14 July 2026 and is supported until July 2028 — [CG Channel](https://www.cgchannel.com/2026/07/blender-5-2-lts-is-here-discover-its-5-key-features/), [Blender 5.2 release page](https://www.blender.org/releases/5-2/)
- Blender 5.2 EEVEE notes: "EEVEE now supports the same instancing optimizations as Workbench and Overlay, leading to CPU-bottlenecked, instancing-heavy scenes being up to twice as fast"; screen-space raytracing pipeline overhauled (existing projects may look different); lights support camera-ray visibility; slightly lower video memory use; larger shadow-pool options — [Blender 5.2 EEVEE release notes](https://developer.blender.org/docs/release_notes/5.2/eevee/)
- A MacRumors forum post reported 100 frames of an EEVEE scene taking about 290 s on an M1 Max (about 2.9 s/frame), Blender 3.4 era, resolution and scene not given (search summary, not opened) — [MacRumors thread](https://forums.macrumors.com/threads/3d-rendering-on-apple-silicon-cpu-gpu.2269416/page-59)
- A Blender Artists post reported EEVEE at about one frame every 15–28 s at 1080p with 64 samples on "M1 Macs" (chip not named), against 4–6 s on an RTX 2070 for the same scene (search summary, not opened; exact post not verified) — [Blender Artists thread](https://blenderartists.org/t/mac-m3-hardware-accelerated-rt-part-1/1264658?page=40)
- A Minecraft rain test rendered in EEVEE reported about 9 s per frame, 1.5 hours total; hardware and resolution not given (search summary, not opened) — [YouTube](https://www.youtube.com/watch?v=5Qzhvi8B8Bg)
- A GTX 1080 Ti test in Blender 2.8: 628 Full HD frames in 27 minutes, about 2.6 s/frame (search summary, not opened) — [ArtStation](https://www.artstation.com/artwork/6awnEN)
- A render-farm page with data dated September 2026 lists a median of 0.76 s per EEVEE image across its customers' scenes, hardware unspecified (search summary, not opened) — [geturna.com](https://geturna.com/en/blender-benchmarks)
- An open Blender bug report is titled "Eevee Next - poor performance on macOS" (search result title only) — [Blender issue #113857](https://projects.blender.org/blender/blender/issues/113857)
- MCprep 3.6.0 removed its Cycles optimiser and added EEVEE Next support — [MCprep releases](https://github.com/Moo-Ack-Productions/MCprep/releases)

### Inferences
- Arithmetic for 30 fps × 40 s = 1200 frames: at 1 s/frame ≈ 20 min; 3 s/frame ≈ 1 h; 9 s/frame ≈ 3 h; 15–28 s/frame ≈ 5–9.3 h. A blocky scene with a few thousand visible faces, nearest-filtered textures, one sun light and modest sample counts sits at the cheap end of EEVEE workloads, so "tens of minutes to about an hour" is the plausible band; raytracing, volumetrics, many shadowed lights or high TAA sample counts push it toward hours. This is an estimate, not a measurement.
- Cycles on an M1 Max (Metal GPU) would typically be several times to an order of magnitude slower per frame than EEVEE for the same shot; for 1200 frames that means many hours to overnight unless samples are kept very low with denoising. No specific Cycles figure for this case was found.
- Cost levers specific to this format: render at 24 or 15 fps on twos for a deliberately "stop-motion" look (halves or quarters the frames), render only the shots that need 3D (a 40 s short rarely needs 40 s of continuous 3D), and reuse a static environment with only the character and changed blocks animated.
- Scene build time (importing/meshing the world, loading textures) is a fixed cost per shot on top of per-frame time and can dominate very short clips.

### Gaps
- No controlled benchmark of EEVEE in Blender 5.x on M1 Max at 1080×1920 was found; all figures above are anecdotes from older versions or unspecified hardware.
- No Minecraft-scene-specific EEVEE timing on Apple Silicon was found.
- The current status of the macOS EEVEE performance issue (#113857) in 5.2 was not checked.

## 7. Licensing: Mojang/Microsoft Usage Guidelines and EULA; MCprep's stance

### Takeaway
The current Usage Guidelines explicitly permit monetised videos "of you playing or using Minecraft" (footage, free to view, with enough of your own content), but they say nothing explicit about animations built from extracted textures and models; such use falls under the general "assets" rules, is tolerated in practice (MCprep exists openly and requires a legal copy), and is revocable at Mojang's discretion. The naming rule matters directly here: "Minecraft" may not be the primary or dominant part of a channel, series or product name, and a "not official" disclaimer is expected.

### Cited Findings
All quotations in this block are from the page as served on 2026-11-26 (page footer "© 2026 Mojang AB"; the page shows no "last updated" date) — [Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)
- Definitions: "Our assets, we mean the code, software, graphics, textures, images, models, sounds and other audio from any of our games and any videos or screenshots taken from our games." "Our brand, we mean any names, related logos, fonts, textures, and any other distinctive characteristics of any part of our name and games."
- Status of the guidelines: they "do not form part of the policies [EULA etc.]"; "All permissions and consents are given by us at our discretion and may be revoked at any time if we think that it is appropriate to do so, or we don't like what you are doing"; "We are not able to give advice about whether a specific project does or does not comply with these guidelines."
- Essential rules for any use of name, brand or assets: do not make people think it is "official or approved by, endorsed by, associated with, supported by, or connected to us"; "Do not redistribute our games or any alterations of our games or game files"; "Do not make commercial use or commercially exploit anything that we have made unless these guidelines say it's okay"; "Prominently include the disclaimer similar to the following: 'NOT AN OFFICIAL MINECRAFT [PRODUCT/SERVICE/EVENT/etc.]. NOT APPROVED BY OR ASSOCIATED WITH MOJANG OR MICROSOFT' on your product, listing, description, website/webpage, and all other related materials."
- Naming: "You may use our name in connection with your product or service, title, or listing (including on websites, video platforms, or merchandise)" if it is in "a secondary name, secondary title, or description", is "necessary to describe your creations or their purpose honestly and fairly", "is not the dominant element or the distinctive part of the complete name or title", and you "Don't use any other aspect of any of our brand or assets as part of any related branding, including as a logo or part of a logo". "You may not use the Minecraft name as the primary or dominant name or title." Examples: "Kotoba Miners: A Minecraft server for Redstone builds" (allowed); "Minecraft – the ultimate help app" (not allowed); "The Shaft – a Minecrafter's podcast" (allowed).
- "Commercial use means any uses of our name, brand, or assets that you use and share with others (regardless of whether you receive payment or provide it for free). This can be through videos and streams you create..."
- Videos: "You are allowed to create, use, and share videos, streams, and screenshots of you playing or using Minecraft. You may also make money from your videos and streams, through ad revenue, if you follow the guidelines in this section." Conditions include: all videos free to view (no paywall); "You add enough of your own unique content to the video or stream to make it reasonable for you to make money through someone watching it" (own commentary counts; just a logo or overlay on gameplay does not); "You don't create and use videos or streams whose purpose is to advertise or promote products or services unrelated to Minecraft"; title cards, credits and sponsorship notices go "outside of the actual game content"; "You don't sell copies of the videos or streams."
- Constructed promotions: companies, brands, agencies and "individual artists, and other entities are not permitted to use Minecraft gameplay to promote or market products, services, events, campaigns, or brands unrelated to Minecraft without prior written approval".
- Mods: defined as "an original plug-in that extends the functionality of Minecraft but that doesn't contain a substantial part of our copyrightable code or content"; may be distributed if you distribute "the mod only and not a modded version of Minecraft".
- Fair use: "You may do things that are specifically covered by the fair dealing or fair use exceptions to copyright and trademark laws."
- Catch-all: "If something isn't covered by these guidelines and we haven't otherwise said it's okay, that probably means we don't want you to do it. In any case if it isn't covered, please don't do it without getting written permission from us."
- The word "animation" does not appear anywhere in the guidelines text (checked by text search of the fetched page) — [Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)
- Mojang's help centre states that you may create videos of Mojang games, upload or stream them and monetise them (search summary; the article timed out when opened) — [Mojang help: Content Creation and Broadcasting Terms](https://help.minecraft.net/hc/en-us/articles/34348618194189-Content-Creation-and-Broadcasting-Terms-of-Use-and-Guidelines)
- Third-party trackers report revisions of the guidelines dated 10 July 2026 and 4 August 2026 (search summary, not opened; not confirmed on the official page) — [ConductAtlas](https://conductatlas.com/platform/minecraft/minecraft-usage-guidelines/)
- MCprep's stance: it bundles a vanilla-texture default pack and rigs, and states "To use MCprep with assets, you must have a valid, legal copy of Minecraft to comply with Mojang's terms of service"; asset-free versions "are not bound to this requirement"; it displays the "NOT AN OFFICIAL MINECRAFT PRODUCT..." disclaimer — [MCprep README](https://github.com/Moo-Ack-Productions/MCprep), [MCprep releases](https://github.com/Moo-Ack-Productions/MCprep/releases)
- jmc2obj by default takes textures from the user's installed Minecraft ("If omitted, will attempt to use the default Minecraft pack"), i.e. from the user's own licensed copy — [CmdLineParser.java](https://github.com/jmc2obj/j-mc-2-obj/blob/master/src/org/jmc/CmdLineParser.java)

### Inferences
- What is clearly permitted: monetised, free-to-view videos with the creator's own commentary/content that show Minecraft footage; using the name descriptively and secondarily ("X – an AI bot that plays Minecraft"); a devlog about a Minecraft bot is Minecraft-related, so it is not a "constructed promotion" of an unrelated product.
- What is a grey area: a Blender re-creation using Mojang's textures and block/mob models is use of "assets" but is not literally "footage of our game", so the explicit video permission does not obviously cover it, and the catch-all says uncovered uses are probably unwanted. In practice fan animation made this way is a long-standing, openly tolerated genre (MCprep, MiEx's page citing use in Minecraft Live videos, Blender Studio's Minecraft animation workshop), and Mojang's own definition of commercial use lists "videos and streams you create" as an example. The realistic risk is low but the permission is informal and revocable.
- What to avoid regardless of route: a channel, series or handle where "Minecraft" is the first or dominant word; Minecraft logo, logo-style lettering or official key art in thumbnails/branding; anything implying endorsement; redistributing game files (for example publishing .blend files or asset packs that contain vanilla textures); paywalled video copies.
- Project-specific flag: the repository/project name "minecraft-gpt" has "Minecraft" as its first and dominant word. For a public channel or series title, the guidelines' own examples ("Minecraft – the ultimate help app" not allowed) suggest choosing a distinct primary name with Minecraft only in the subtitle or description, plus the standard disclaimer in channel and video descriptions.
- If the bot itself were ever sold as a product, video promotion of it would be commercial use of the name and, with game textures on screen, of assets; the original-asset route (section 5) reduces exposure there.

### Gaps
- The Minecraft EULA text itself was not fetched; nothing above is quoted from the EULA. The guidelines say they sit alongside the EULA and are not part of it.
- No official Mojang statement was found that addresses fan animations rendered outside the game with extracted assets, in either direction.
- The exact date of the last revision of the Usage Guidelines could not be confirmed from the official page.
- Rules specific to YouTube/TikTok handles (as opposed to "name or title") are not spelled out in the guidelines; the general naming rule is the only text.
- Minecraft music/sound use (C418 etc.) in re-created animation was not researched; the guidelines list "sounds and other audio" as assets.

## 9. Effort estimate: minimum viable version vs a general "replay any bot session in Blender" system

### Takeaway
A minimum viable clip (one bot character, one small scene, 10 seconds, vertical) is a few days of work on top of the creator's existing headless Blender + Remotion pipeline, and almost all parts are scriptable. A general system that replays arbitrary sessions with correct blocks, mobs, items, lighting and watchable camera work is a multi-week to multi-month project with a long tail of special cases, and the camera/editing judgement does not automate away.

### Cited Findings
- Scriptable building blocks that already exist: jmc2obj command line with `--area`, `--height`, `--resource-pack`, `--offset`, `--object-per-block` — [CmdLineParser.java](https://github.com/jmc2obj/j-mc-2-obj/blob/master/src/org/jmc/CmdLineParser.java); Mineways `.mwscript` with coordinate selection and experimental `-headless` — [Mineways scripting](https://www.realtimerendering.com/erich/minecraft/public/mineways/scripting.html); MCprep operators for world import, material prep, mob/player spawn and skin swap, exercised in `--background` by its tests — [world_tools_test.py](https://github.com/Moo-Ack-Productions/MCprep/blob/master/test_files/world_tools_test.py), [run_tests.py](https://github.com/Moo-Ack-Productions/MCprep/blob/master/run_tests.py)
- Version friction for 26.1: jmc2obj's 26.1 world loading is only in unreleased commits (Aug 2026); Mineways supports 26.3 and earlier but is Windows-first; MCprep resources go to 26.2 "excluding mobs" — [jmc2obj commits](https://github.com/jmc2obj/j-mc-2-obj/commits/master), [Mineways home](https://www.realtimerendering.com/erich/minecraft/public/mineways/), [MCprep releases](https://github.com/Moo-Ack-Productions/MCprep/releases)
- No off-the-shelf importer from schematic or bot data works on macOS today (Mine2Blend is Windows-only beta) — [Mine2Blend README](https://github.com/CAT-YC/Mine2Blend)
- prismarine-viewer offers a headless video recorder and a 3D-model exporter example driven from Mineflayer data — [prismarine-viewer README](https://github.com/PrismarineJS/prismarine-viewer), [exporter example](https://github.com/PrismarineJS/prismarine-viewer/tree/master/examples/exporter)

### Inferences
**Minimum viable version (one bot rig, one small scene, 10 s = 300 frames at 30 fps)**
- Bot side (about half a day to a day): a recorder that writes a JSON timeline at tick rate: `t, pos, yaw, pitch, onGround, heldItem`, plus events `dig start/finish`, `place`, `attack`, `blockUpdate`, and a one-off block snapshot of a small box (for example 32×24×32) at the start. In this codebase the natural hook points are the action primitives in `src/core/primitives.ts` (every game-changing call already passes through them) and Mineflayer's `move`/`blockUpdate` events; the recorder is read-only and does not touch the arbiter.
- Scene side (1–2 days): either jmc2obj → OBJ → MCprep `prep_materials` on a local world save (1.21.x is safe today; 26.1 needs a jmc2obj beta build), or a simple own mesher for full cubes with a flat-colour or self-made palette. For a 10 s proof, full-cube-only is acceptable.
- Character side (1–2 days): MCprep player rig + `applyskin`, or a six-box armature generated in code; root motion from the log, distance-driven limb swing, arm-swing action on dig/place events, held item swap.
- Camera, light, render, Remotion hand-off (about a day): one follow camera with smoothing, sun + sky, EEVEE, PNG sequence into the existing Remotion edit.
- Total: roughly 3–6 working days for the first clip, less with an AI agent writing the bpy scripts through the Blender MCP server; later clips of the same kind cost mostly render time and camera tweaking. The part an agent can do well: generating and iterating the bpy code, building the scene from JSON, placing keyframes. The part that still needs a human eye: whether the shot reads on a phone screen.

**General "replay any bot session" system**
- Additional work items: correct geometry for non-cube blocks and block states (stairs, slabs, fences, doors, crops, torches, water/lava, chests opening); block-break crack stages and place/break particles; item entities, pickups, crafting/furnace/chest interactions (needs UI stand-ins, since inventories are 2D screens in the game); other entities (mobs, the owner's player) with their own logged tracks and per-mob rigs/animations; combat, damage and death; day/night and light levels, caves and night scenes that are readable; dimension changes (Nether, End); long sessions that cross many chunks (streaming or per-shot region selection); automatic shot selection and camera direction; keeping up with new Minecraft versions (new blocks need textures/models; MCprep mobs lag).
- Estimate: 4–8 weeks to a robust "walk, mine, place, fight a few common mobs in the overworld by day" replayer; open-ended beyond that. Each category above is individually small but they add up, and the output is only as good as its weakest visible element.
- A staged path keeps risk low: (1) MVP clip; (2) parametrise it into "render a clip from timeline X between t0 and t1 with camera preset Y"; (3) add block states and mobs only when a planned episode needs them.
- Decision-relevant comparison: filming the real game (or prismarine-viewer headless) gives true-to-life footage for near-zero build cost; the Blender route buys full camera freedom, a consistent cartoon look shared with the creator's other series, reuse of an existing automated pipeline, and (with original assets) cleaner licensing, at the price of building and maintaining a renderer for a subset of the game.

### Gaps
- All durations are my estimates from the scope of work; no published effort data for a comparable project was found.
- The estimate assumes the existing Blender 5.2 + Remotion pipeline is reusable as-is for a second series; I did not inspect that pipeline.
- Whether jmc2obj's Actions beta build is stable on 26.1 worlds, and whether MCprep's `prep_materials` handles its output on Blender 5.2 without manual fixes, needs a hands-on test before committing to the vanilla-look path.
